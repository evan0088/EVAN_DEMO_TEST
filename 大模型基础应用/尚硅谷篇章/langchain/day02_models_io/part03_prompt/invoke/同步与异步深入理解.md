# 同步 vs 异步：LangChain 模型调用深入理解

## 一、文件结构概览

```
invoke/
├── LLM_Invoke.py       # 同步 — 单条请求
├── LLM_Batch.py        # 同步 — 批量请求
├── LLM_Stream.py       # 同步 — 流式响应
├── LLM_aInvoke.py      # 异步 — 单条请求 (ainvoke)
├── LLM_aBatch.py       # 异步 — 批量请求 (abatch)
└── LLM_aStream.py      # 异步 — 流式响应 (astream)
```

**命名规律**：异步版本 = 同步版本文件名前缀加 `a`（async 的首字母）。

## 二、核心差异对照

### 2.1 语法层面

| | 同步 (Sync) | 异步 (Async) |
|---|---|---|
| 函数定义 | 普通函数 | `async def` |
| 调用方式 | 直接调用 | `await` 或 `async for` |
| 入口驱动 | 直接执行 | `asyncio.run()` |
| 适用场景 | 脚本 / CLI / 简单任务 | Web 服务 (FastAPI) / 高并发 |

### 2.2 三种调用模式的对比

#### 单条请求 — invoke / ainvoke

```python
# LLM_Invoke.py — 同步
response = model.invoke(messages)
print(response.content)

# LLM_aInvoke.py — 异步
response = await model.ainvoke(messages)
print(response.content_blocks)
```

| 要点 | 说明 |
|---|---|
| 同步 `invoke` | 直接调用，阻塞等待结果返回 |
| 异步 `ainvoke` | 必须加 `await`，不会阻塞事件循环 |
| 返回值 | 都是 `AIMessage`，`.content` 获取文本内容 |

#### 批量请求 — batch / abatch

```python
# LLM_Batch.py — 同步
response = model.batch(questions)
for q, r in zip(questions, response):
    print(f"问题：{q}\n回答：{r.content}\n")

# LLM_aBatch.py — 异步
response = await model.abatch(questions)
for q, r in zip(questions, response):
    print(f"问题：{q}\n回答：{r.content}\n")
```

| 要点 | 说明 |
|---|---|
| 同步 `batch` | 顺序执行多个请求，总耗时 = 所有请求耗时之和 |
| 异步 `abatch` | 并发执行，总耗时 ≈ 最慢的那个请求耗时 |
| 参数形式 | 都接收 `List[str]` 或 `List[BaseMessage]` |
| 返回类型 | 都是 `List[AIMessage]` |

> `abatch` 是异步批量调用的核心优势所在 — 多个请求不互相阻塞。

#### 流式响应 — stream / astream

```python
# LLM_Stream.py — 同步
response = model.stream(messages)   # 返回 Generator
for chunk in response:
    print(chunk.content, end="", flush=True)

# LLM_aStream.py — 异步
response = model.astream(messages)  # 返回 async_generator
async for chunk in response:
    print(chunk.content, end="", flush=True)
```

| 要点 | 说明 |
|---|---|
| 同步 `stream` | 返回普通生成器，用 `for` 遍历 |
| 异步 `astream` | 返回异步生成器，用 `async for` 遍历 |
| 共同点 | 都通过 `chunk.content` 逐块获取内容 |
| `flush=True` | 刷新缓冲区实现即时输出（两边都需要！） |

> **对 `astream` 不需要 `await`！** 因为 `model.astream(messages)` 返回的是异步生成器对象，而不是一个可等待的协程。`async for` 在每次迭代时隐式 `await` 下一个数据块。

## 三、异步的核心机制

### 3.1 async / await

```python
async def async_batch_call():
    response = await model.abatch(questions)  # 挂起但不阻塞
    ...
```

- `async def`：定义一个协程函数，调用它返回一个协程对象，不会立即执行
- `await`：挂起当前协程，等待结果回来再继续往下走
- 挂起期间，事件循环可以切换去执行另一个协程

### 3.2 asyncio.run()

```python
if __name__ == "__main__":
    asyncio.run(async_batch_call())
```

- 创建一个事件循环
- 运行传入的协程直到完成
- 完成后自动关闭事件循环
- 一个进程通常只调用一次

### 3.3 async for

```python
async for chunk in model.astream(messages):
    print(chunk.content, end="", flush=True)
```

- 用于遍历异步生成器或异步迭代器
- 每次迭代时，内部会 `await` 下一个值
- 不能用在普通 `for` 循环里，反之亦然

## 四、值得注意的细节与坑

### 4.1 API Key 环境变量不一致

| 文件 | 环境变量名 |
|---|---|
| `LLM_Invoke.py` | `DASHSCOPE_API_KEY` |
| `LLM_Batch.py` | `DASHSCOPE_API_KEY` |
| `LLM_Stream.py` | **DASHSCOPE_API_KEY** |
| `LLM_aInvoke.py` | `DASHSCOPE_API_KEY` |
| `LLM_aBatch.py` | `DASHSCOPE_API_KEY` |
| `LLM_aStream.py` | **DASHSCOPE_API_KEY** |

可能是书写不一致。如果用的是同一个通义千问的 API，应统一用同一个变量名，避免 `.env` 配置不生效。

### 4.2 load_dotenv() 被注释

`LLM_Invoke.py` 中 `load_dotenv()` 被注释掉了：

```python
# load_dotenv()
```

如果 `.env` 文件存在但没被加载，`os.getenv("DASHSCOPE_API_KEY")` 会返回 `None`，导致模型初始化失败。

### 4.3 异步打印内容属性不一致

`LLM_aInvoke.py` 中：

```python
print(response.content_blocks)  # 用了 content_blocks
```

而其余文件都用：

```python
print(response.content)  # 标准用法
```

`content_blocks` 返回的是结构化的内容块列表（可能在多模态场景下有用），而 `.content` 返回纯文本字符串。这个区别需要根据实际需求选择，但和其他文件不统一容易造成混淆。

### 4.4 stream 不需要 await

最容易混淆的地方：

```python
# 正确 — stream 返回生成器，不需要 await
resp = model.stream(messages)     # 同步生成器
resp = model.astream(messages)    # 异步生成器

# 错误写法
resp = await model.astream(messages)  # TypeError
```

记忆口诀：**await 动词，async for 名词** — `await` 加在调用动作上（`await model.ainvoke()`），`async for` 加在遍历对象上（`async for chunk in model.astream()`）。

### 4.5 flush=True 的作用

```python
print(chunk.content, end="", flush=True)
```

- `end=""`：取消默认的换行，让内容拼在一行
- `flush=True`：强制刷新输出缓冲区，否则内容可能攒在缓冲区里不会立即打印，就失去了"流式"的效果

### 4.6 async for 的注释强调

`LLM_aStream.py` 中把"必须使用 `async for`，不可用普通 `for`"重复写了三遍 — 这确实是新手最容易踩的坑。异步生成器只能用 `async for` 遍历，反过来，普通生成器也不能用 `async for`。

## 五、什么时候该用异步？

### 推荐使用异步的场景

| 场景 | 原因 |
|---|---|
| **FastAPI / Web 服务** | 异步不阻塞 worker 线程，可以同时服务更多请求 |
| **批量调用多个模型** | `abatch` 并发请求大幅缩短总耗时 |
| **同时调用不同服务** | 例如同时调 LLM + 数据库 + 外部 API |
| **高并发 / I/O 密集型** | LLM 调用本质是 I/O 等待，异步最擅长 |

### 仍然可以用同步的场景

| 场景 | 原因 |
|---|---|
| **一次性脚本** | 没有并发需求，同步写起来更简单直接 |
| **单条调用** | `invoke` 和 `ainvoke` 对单条请求来说效果一样 |
| **学习/调试** | 同步代码更直观，方便加断点调试 |

## 六、速查表

| 功能 | 同步写法 | 异步写法 |
|---|---|---|
| 导入 | `import os` | `import os; import asyncio` |
| 函数定义 | `def func():` | `async def func():` |
| 单条调用 | `model.invoke(x)` | `await model.ainvoke(x)` |
| 批量调用 | `model.batch(x)` | `await model.abatch(x)` |
| 流式调用 | `for c in model.stream(x)` | `async for c in model.astream(x)` |
| 遍历结果 | `for item in response:` | `async for item in response:` |
| 入口 | 直接执行 | `asyncio.run(main())` |

---

## 七、总结一句话

> **同步 = 排队做事，做完一件再干下一件；异步 = 同时点外卖、洗衣、写代码 — 等结果时不闲着。**

具体到 LangChain：
- 方法名前加 `a` = 异步版本
- `ainvoke` / `abatch` 需要 `await`
- `astream` 不需要 `await`，但需要用 `async for` 遍历
- 异步代码必须用 `asyncio.run()` 驱动
