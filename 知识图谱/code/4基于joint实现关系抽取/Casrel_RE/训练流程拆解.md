### 3.3 `collate_fn` — 批次整理函数

**文件**: [codes/utils/process.py:81-129](codes/utils/process.py#L81-L129)

这是数据预处理的核心，流程如下：

```
Step 1: 提取 batch 中所有文本 → tokenizer.batch_encode_plus(padding=True)
        → 得到 input_ids（形状 [batch_size, seq_len]）
        → 得到 attention_mask（形状 [batch_size, seq_len]）

Step 2: 遍历 batch 中每个样本:
    ┌─ 调用 create_label(inner_triples, inner_input_ids, seq_len)
    │  返回: (sub_len, sub_head2tail, sub_heads, sub_tails, obj_heads, obj_tails)
    │
    │  create_label 内部逻辑（见 3.4）:
    │  1. 初始化全零张量: sub_heads[seq_len], sub_tails[seq_len]
    │                      obj_heads[seq_len, num_rel], obj_tails[seq_len, num_rel]
    │                      sub_head2tail[seq_len]
    │  2. 遍历该样本所有三元组 (s, p, o):
    │     - 用 tokenizer 把 s 和 o 转为 token id 列表
    │     - 用 find_head_idx() 在 input_ids 中定位 s 和 o 的起止位置
    │     - 存入 s2ro_map: { (sub_head, sub_tail): [(obj_head, obj_tail, rel_id), ...] }
    │  3. 在 sub_heads/sub_tails 的对应位置标记为 1
    │  4. 随机选一个主实体，填充 sub_head2tail（从 head 到 tail 全为 1）
    │  5. 在该主实体对应的 obj_heads/obj_tails 上标记客实体位置和关系类型

Step 3: 将所有样本的结果 stack 成 batch 维度 → 返回 (inputs, labels)
```

### 3.4 `create_label` — 标签构造（逐样本）

**文件**: [codes/utils/process.py:41-78](codes/utils/process.py#L41-L78)

```
输入: 一个样本的三元组列表、input_ids、seq_len
输出: (sub_len, sub_head2tail, sub_heads, sub_tails, obj_heads, obj_tails)

关键数据结构 s2ro_map:
  {
    (sub_head_idx, sub_tail_idx): [
      (obj_head_idx, obj_tail_idx, rel_id),
      ...
    ],
    ...
  }
  # 例如: {(3, 5): [(7, 8, 0)]} 表示主实体在位置3-5，客实体在位置7-8，关系ID为0

处理要点:
  - sub_heads[i] = 1   → 位置 i 是某个主实体的开头
  - sub_tails[j] = 1   → 位置 j 是某个主实体的结尾
  - obj_heads[k][rel] = 1 → 位置 k 是关系 rel 的客实体开头
  - obj_tails[k][rel] = 1 → 位置 k 是关系 rel 的客实体结尾
  - sub_head2tail      → 随机选一个主实体，从其开头到结尾全标记为1
  - 防止零除: sub_len 初始化为 1，即使无三元组也不会报错
```

### 3.5 最终 batch 的数据结构

```python
# inputs（喂给模型的输入）
inputs = {
    'input_ids':     torch.Size([batch_size, seq_len]),      # token id
    'mask':          torch.Size([batch_size, seq_len]),      # attention mask
    'sub_head2tail': torch.Size([batch_size, seq_len]),      # 主实体头到尾的掩码
    'sub_len':       torch.Size([batch_size, 1]),            # 主实体长度
}

# labels（用于计算损失的真实标签）
labels = {
    'sub_heads': torch.Size([batch_size, seq_len]),          # 主实体头部位置
    'sub_tails': torch.Size([batch_size, seq_len]),          # 主实体尾部位置
    'obj_heads': torch.Size([batch_size, seq_len, num_rel]), # 客实体头部 + 关系
    'obj_tails': torch.Size([batch_size, seq_len, num_rel]), # 客实体尾部 + 关系
}
```

## 四、CasRel 模型结构

**文件**: [codes/model/casrel_model.py](codes/model/casrel_model.py)

### 4.1 模型初始化 `__init__`

```
CasRel(nn.Module)
  ├── self.bert              ← BertModel.from_pretrained(bert_path)
  ├── self.sub_heads_linear  ← Linear(768, 1)    # 主实体头部二分类器
  ├── self.sub_tails_linear  ← Linear(768, 1)    # 主实体尾部二分类器
  ├── self.obj_heads_linear  ← Linear(768, 18)   # 客实体头部 + 18种关系分类器
  └── self.obj_tails_linear  ← Linear(768, 18)   # 客实体尾部 + 18种关系分类器
```

### 4.2 前向传播 `forward` — 三步走

```
┌─────────────────────────────────────────────────────────────────┐
│  Step 1: 文本编码                                                │
│  encoded_text = self.bert(input_ids, attention_mask=mask)[0]     │
│  形状: [batch_size, seq_len, 768]                                │
├─────────────────────────────────────────────────────────────────┤
│  Step 2: 主实体预测 (Subject Tagger)                             │
│  pred_sub_heads = sigmoid( sub_heads_linear(encoded_text) )      │
│  pred_sub_tails = sigmoid( sub_tails_linear(encoded_text) )      │
│  形状: [batch_size, seq_len, 1]                                  │
├─────────────────────────────────────────────────────────────────┤
│  Step 3: 客实体 + 关系预测 (Relation-specific Object Tagger)     │
│                                                                  │
│  3a. 将主实体信息融入文本:                                        │
│      sub = matmul(sub_head2tail, encoded_text)   # 提取主实体向量 │
│      sub = sub / sub_len                         # 平均（防过长） │
│      encoded_text = encoded_text + sub           # 融合到每个位置  │
│                                                                  │
│  3b. 在融合后的文本上预测客实体:                                   │
│      pred_obj_heads = sigmoid( obj_heads_linear(encoded_text) )  │
│      pred_obj_tails = sigmoid( obj_tails_linear(encoded_text) )  │
│      形状: [batch_size, seq_len, 18]                             │
└─────────────────────────────────────────────────────────────────┘

返回:
result_dict = {
    'pred_sub_heads': ...,
    'pred_sub_tails': ...,
    'pred_obj_heads': ...,
    'pred_obj_tails': ...,
    'mask': mask           # 传回 mask 用于损失计算时的掩码
}
```

> **设计要点**: 与传统的"先抽主实体再抽客实体"pipeline 不同，CasRel 在训练时直接使用**真实的主实体标注**（`sub_head2tail`）来融合信息，让模型学会在给定主实体的条件下预测客实体和关系。推理时则先用 Step 2 的预测结果作为 Step 3 的输入。

### 4.3 损失计算 `compute_loss`

```
总损失 = loss_1 + loss_2 + loss_3 + loss_4

loss_1 = BCE(pred_sub_heads, sub_heads)   # 主实体头部损失
loss_2 = BCE(pred_sub_tails, sub_tails)   # 主实体尾部损失
loss_3 = BCE(pred_obj_heads, obj_heads)   # 客实体头部 + 关系损失
loss_4 = BCE(pred_obj_tails, obj_tails)   # 客实体尾部 + 关系损失

每个 BCE 损失都按 mask 加权平均:
  loss = sum(BCE(pred, gold) * mask) / sum(mask)

对于客实体损失 (loss_3, loss_4):
  rel_mask = mask.unsqueeze(-1).repeat(1, 1, num_rel)
  将 2D mask 扩展到 3D，匹配 [batch, seq_len, num_rel] 的形状
```

## 五、核心张量/矩阵全景解析

本节逐一解释训练流程中**每一个张量的物理含义、形状变化和设计动机**，帮助理解 CasRel 为什么要这样建模。

### 5.1 数据输入侧张量

#### ① `input_ids` — BERT 输入 token 序列

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len]` 例如 `[8, 200]` |
| **含义** | 每个位置存储一个 token 的整数 ID（如 `[CLS]=101`, `我=2769`），由 BERT 的 tokenizer 将原始文本映射而来 |
| **来源** | `tokenizer.batch_encode_plus(text_list, padding=True)` 按 batch 内最长句子 padding 到统一长度 |
| **为什么需要** | BERT 模型的唯一输入格式，模型内部通过 Embedding 层将每个 ID 映射为 768 维稠密向量 |

#### ② `mask` (attention_mask) — 有效 token 掩码

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len]` 例如 `[8, 200]` |
| **含义** | **1** = 真实 token，**0** = `[PAD]` 填充位 |
| **来源** | `tokenizer.batch_encode_plus` 同步产出 |
| **为什么需要** | **双重作用**：① BERT 的 Self-Attention 忽略 PAD 位置（避免无意义交互）；② 损失函数中对 PAD 位置不计算 loss（避免模型被迫学习填充位的无意义标签） |

#### ③ `sub_head2tail` — 被选中的主实体跨度掩码

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len]` 例如 `[8, 200]` |
| **含义** | 从样本的所有主实体中**随机选一个**，将其在原文中的起止区间（如位置 3~5）全部标记为 **1**，其余位置为 **0**。例如 `[0,0,0,1,1,1,0,...,0]` 表示被选中主实体占据第 3~5 个 token |
| **来源** | `create_label()` 中 `choice(list(s2ro_map.keys()))` 随机选取 + `inner_sub_head2tail[head:tail+1] = 1` |
| **为什么需要** | **这是 CasRel 的核心设计**。Step 2（主实体识别）和 Step 3（客实体+关系识别）是级联关系——Step 3 需要知道"当前在讨论哪个主实体"。训练阶段直接使用**标注的真实主实体**位置作为条件，让模型学会"给定主实体 X，找出它的所有客实体和关系"。推理阶段则用 Step 2 的预测结果替代 |

> **为什么不把所有主实体都告诉 Step 3？** 一次只给一个主实体，能让模型学到"一个主实体 → 多个 (关系, 客实体)"的一对多映射。每次随机选不同的主实体，多轮训练后所有主实体都会被覆盖，相当于一种数据增强。

#### ④ `sub_len` — 被选中主实体的长度

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, 1]` 例如 `[8, 1]` |
| **含义** | 被选中主实体的 token 个数，如 `[3.0]` 表示该实体占 3 个 token |
| **来源** | `sub_tail_idx + 1 - sub_head_idx` |
| **为什么需要** | 在 Step 3 融合阶段用于**归一化**——不同主实体的 token 数不同（"张三"=2 tokens，"北京大学出版社"=6 tokens），直接将多 token 向量相加会导致长实体向量幅值远大于短实体。除以 `sub_len` 实现**按 token 平均**，消除长度偏差 |

---

### 5.2 标签侧张量

#### ⑤ `sub_heads` — 主实体头部位置标签

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len]` 例如 `[8, 200]` |
| **含义** | 多标签二值向量：位置 i 是**某个**主实体的**开头** token → **1**，否则 → **0**。一个句子可能有多个主实体，因此可以有多个位置为 1 |
| **来源** | `create_label()` 遍历 `s2ro_map` 的所有 key：`inner_sub_heads[s[0]] = 1` |
| **为什么需要** | 训练 Step 2 的**主实体头部检测器**——让模型学会判断"每个 token 是否是某个实体的开始" |

#### ⑥ `sub_tails` — 主实体尾部位置标签

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len]` 例如 `[8, 200]` |
| **含义** | 多标签二值向量：位置 i 是**某个**主实体的**结尾** token → **1**，否则 → **0** |
| **来源** | `create_label()` 遍历 `s2ro_map` 的所有 key：`inner_sub_tails[s[1]] = 1` |
| **为什么需要** | 训练 Step 2 的**主实体尾部检测器**——配合 `sub_heads`，通过 head-tail 配对解码出完整的实体跨度。采用"首尾独立标注"而非"BIO 序列标注"，优势是**不受实体嵌套和重叠限制** |

#### ⑦ `obj_heads` — 客实体头部 + 关系联合标签

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len, num_rel]` 例如 `[8, 200, 18]` |
| **含义** | 三维张量：`obj_heads[i][r] = 1` 表示"token i 是**被选中主实体**在关系 r 下的**客实体开头**"。每一层（沿 dim=-1）对应一种关系类型，互不干扰 |
| **来源** | `create_label()` 只对**被随机选中的主实体**填充：`inner_obj_heads[ro[0]][ro[2]] = 1` |
| **为什么需要** | **同时完成"客实体定位"和"关系分类"**。传统 pipeline 方法是先抽实体再分类关系，但 CasRel 将两者合并到一个三维标注空间中——关系类型直接编码到第三个维度，一次前向传播即可得到 (客体位置, 关系类型) 的完整预测 |

#### ⑧ `obj_tails` — 客实体尾部 + 关系联合标签

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len, num_rel]` 例如 `[8, 200, 18]` |
| **含义** | 与 `obj_heads` 对称：`obj_tails[j][r] = 1` 表示"token j 是被选中主实体在关系 r 下的客实体结尾" |
| **来源** | `create_label()` 中 `inner_obj_tails[ro[1]][ro[2]] = 1` |
| **为什么需要** | 配合 `obj_heads` 通过 head-tail 配对解码客实体跨度。同样按关系类型分层，保证不同关系的客实体不会混淆 |

> **关键设计洞察**：`obj_heads` 和 `obj_tails` 的形状 `[seq_len, num_rel]` 意味着对**每个位置、每种关系**都独立判断。这解决了两个问题：
> 1. **重叠实体**：同一个位置可以同时是多种关系的客实体起点（如"北京"既是"首都"关系又是"位于"关系的客体）
> 2. **多标签**：使用 sigmoid + BCE（而非 softmax + CE），允许多个位置同时为 1

### 5.3 模型前向传播中的中间张量

#### ⑨ `encoded_text` — BERT 编码后的上下文表示

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len, bert_dim]` 即 `[8, 200, 768]` |
| **含义** | 每个 token 的 768 维上下文感知向量。`[CLS]` 位置聚合了全句信息，其他位置融合了双向上下文 |
| **来源** | `self.bert(input_ids, attention_mask=mask)[0]` — 取 BERT 最后一层 hidden state |
| **为什么需要** | 这是所有下游任务的**共享特征基础**。Step 2 的主实体检测和 Step 3 的客实体检测都基于这个表示 |

#### ⑩ `pred_sub_heads` / `pred_sub_tails` — 主实体预测概率

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len, 1]` 例如 `[8, 200, 1]` |
| **含义** | 每个 token 是主实体头部/尾部的**概率**（0~1，经 sigmoid 激活） |
| **来源** | `sigmoid(Linear(encoded_text))` — 每个 token 的 768 维向量 → 1 个标量分数 |
| **为什么是 [..., 1] 而非 [..., ]** | Linear(768, 1) 输出保持最后一维。计算 BCE loss 时通过 `squeeze(-1)` 压平成 `[batch, seq_len]` 与标签对齐 |

#### ⑪ `sub` — 主实体向量（融合前）

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, 1, bert_dim]` 即 `[8, 1, 768]` |
| **含义** | 被选中主实体的**平均向量表示**（将主实体所有 token 的 BERT 向量加权求和后取平均） |
| **来源** | `sub = matmul(sub_head2tail, encoded_text)` → `sub / sub_len` |
| **计算过程** | ① `sub_head2tail` 形状为 `[batch, 1, seq_len]`（由 `[batch, seq_len]` 经 `unsqueeze(1)` 扩维），与 `encoded_text [batch, seq_len, 768]` 做矩阵乘法 → `[batch, 1, 768]`。本质是**将主实体区间内的 token 向量求和**（因为 head2tail 在该区间为 1，其余为 0）。② 除以 `sub_len` → 按 token 数平均 |
| **为什么需要** | 将主实体的"身份信息"编码为一个稠密向量，准备注入到文本表示中 |

> **为什么用 `matmul` 而不是切片求 mean？** 
> - 切片方案：`encoded_text[:, head:tail+1, :].mean(dim=1)` — 需要知道起止索引，batch 内各样本起止不同，无法向量化
> - matmul 方案：`sub_head2tail` 作为软掩码，一次矩阵乘法完成整个 batch 的提取，**完全可向量化，GPU 友好**

#### ⑫ `encoded_text`（融合后）— 注入主实体信息

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len, bert_dim]` 即 `[8, 200, 768]` |
| **含义** | 原始 BERT 表示 **+** 主实体向量（广播到每个 token 位置） |
| **来源** | `encoded_text = encoded_text + sub` |
| **为什么需要** | 让**每个 token 位置都知道"当前关注的主实体是谁"**。Step 3 的线性层在每个位置独立做预测（无 token 间交互），如果不注入主实体信息，模型无法知道该去哪个位置找客实体。这种加法融合是轻量级条件控制——相当于告诉模型："在这个句子里，现在要找与**这个**主实体相关的客实体" |

### 5.4 模型参数矩阵

#### ⑬ `sub_heads_linear` / `sub_tails_linear` — 主实体检测头

| 项目 | 说明 |
|---|---|
| **权重形状** | `[1, 768]`（Linear(768, 1)） |
| **含义** | 学习一个 768 维权重向量，与每个 token 的 BERT 表示做内积 → 一个标量 logit → sigmoid → 概率 |
| **为什么是 Linear(768,1)** | 对每个 token **独立**做二分类（是否为主实体头部/尾部）。本质上等同于 `w · h_i + b`，其中 `w` 是学到的判别方向 |

#### ⑭ `obj_heads_linear` / `obj_tails_linear` — 客实体+关系检测头

| 项目 | 说明 |
|---|---|
| **权重形状** | `[18, 768]`（Linear(768, 18)） |
| **含义** | 学习 18 个独立的 768 维权重向量（每种关系一个），与每个 token 的融合后表示做内积 → 18 维 logit 向量 → sigmoid → 18 维概率 |
| **为什么是 Linear(768,18)** | 对每个 token、每种关系**独立**做二分类。18 个输出通道互不排斥——一个 token 可以同时是多种关系的客体头部。这种设计天然支持 **overlapping relations** |

---

### 5.5 损失计算中的辅助张量

#### ⑮ `rel_mask` — 扩展到关系维度的掩码

| 项目 | 说明 |
|---|---|
| **形状** | `[batch_size, seq_len, num_rel]` 例如 `[8, 200, 18]` |
| **含义** | 将 2D 的 `mask` 沿最后一维复制 `num_rel` 次。`rel_mask[i][j][k] = mask[i][j]`（所有 k 相同） |
| **来源** | `mask.unsqueeze(-1).repeat(1, 1, rel_count)` |
| **为什么需要** | `obj_heads/obj_tails` 的标签和预测都是 3D 的 `[batch, seq_len, num_rel]`，loss 计算需要同形状的掩码来屏蔽 PAD 位置。如果直接用 2D mask 去乘 3D 张量，广播规则可能导致语义错误——显式扩展到 3D 确保语义正确 |

---

### 5.6 推理/解码中的张量

#### ⑯ `obj_heads.T` / `obj_tails.T` — 转置后的客实体预测

| 项目 | 说明 |
|---|---|
| **形状** | 从 `[seq_len, num_rel]` 转置为 `[num_rel, seq_len]` |
| **含义** | 变换视角：从"每个位置属于哪种关系"变为"每种关系在哪些位置有实体" |
| **来源** | `extract_obj_and_rel()` 中的 `obj_heads = obj_heads.T` |
| **为什么需要** | 解码时按关系类型逐行处理——对每种关系 r，取第 r 行作为该关系的 head/tail 预测，调用 `extract_sub()` 恢复实体跨度。转置让按关系遍历变成简单的按行索引 |

---

### 5.7 设计动机总结

| 设计选择 | 解决的问题 |
|---|---|
| **Head-Tail 分离标注** (sub_heads + sub_tails) | 无需预设实体类别数，支持任意长度实体，支持嵌套/重叠 |
| **三维 obj 标签** (seq_len × num_rel) | 客实体定位和关系分类一步完成，避免 pipeline 误差传播 |
| **Sigmoid + BCE**（而非 Softmax + CE） | 多标签场景——一个位置可以同时是多个实体的起止点 |
| **sub_head2tail 随机选一个主实体** | 训练时明确告诉 Step 3 "关注谁"，推理时用 Step 2 预测替代；随机选择 = 隐式数据增强 |
| **sub / sub_len 归一化** | 消除实体长度对向量幅值的干扰 |
| **matmul 提取实体向量**（而非切片） | 向量化操作，充分利用 GPU 并行 |
| **encoded_text + sub 加法融合** | 最轻量的条件信息注入方式，让每个 token 感知"当前在讨论哪个主实体" |
| **rel_mask 显式扩展** | 确保 PAD 位置对所有关系类型都不参与损失计算 |

这是训练流程的核心，逐步拆解如下：

```
┌────────────────────────────────────────────────────────────────┐
│  for step, (inputs, labels) in enumerate(tqdm(train_iter)):   │
│                                                                │
│  ① model.train()                     # 切换到训练模式          │
│     (启用 dropout, 更新 BN 统计量)                              │
│                                                                │

│            pred_obj_heads, pred_obj_tails, mask}               │

│  ④ model.zero_grad()                 # 梯度清零               │

```

## 八、验证评估 — `model2dev()`

**文件**: [codes/train.py:84-153](codes/train.py#L84-L153)

### 8.1 评估流程

```
1. model.eval()                              # 切换到评估模式（禁用 dropout）
2. 初始化 DataFrame 记录 TP / PRED / REAL / p / r / f1
3. for inputs, labels in dev_iter:           # 遍历验证集
     │
     ├─ logist = model(**inputs)             # 前向传播（无梯度）
     │
     ├─ 将预测分数转为 0/1 二值:              # 阈值 = 0.5
     │   convert_score_to_zero_one(pred)     # >=0.5 → 1, <0.5 → 0
     │
     ├─ 逐样本解码:
     │
     │   ┌─ extract_sub(heads, tails):       # 从 head/tail 标记恢复实体跨度
     │   │  heads = indices where value==1
     │   │  tails = indices where value==1
     │   │  配对(head, tail) where tail>=head
     │   │  返回: [(head, tail), ...]
     │   │
     │   └─ extract_obj_and_rel( heads, tails ):  # 从 [seq, rel] 解析客实体
     │       转置 → 按关系类型逐行 extract_sub
     │       返回: [(rel_id, start, end), ...]
     │
     ├─ 统计 TP / PRED / REAL:
     │   df['TP']['sub']   += len( 预测主实体 ∩ 真实主实体 )
     │   df['PRED']['sub'] += len( 预测主实体 )
     │   df['REAL']['sub'] += len( 真实主实体 )
     │   df['TP']['triple']   += len( 预测三元组 ∩ 真实三元组 )
     │   df['PRED']['triple'] += len( 预测三元组 )
     │   df['REAL']['triple'] += len( 真实三元组 )
     │
4. 计算指标（两组）:
   ├─ Sub 指标: precision, recall, f1
   └─ Triple 指标: precision, recall, f1

5. 返回: (sub_precision, sub_recall, sub_f1,
          triple_precision, triple_recall, triple_f1, df)
```

### 8.2 评估指标公式

```
Precision = TP / (PRED + ε)     # ε = 1e-9 防止除零
Recall    = TP / (REAL + ε)
F1        = 2 × P × R / (P + R + ε)
```

- **Sub 指标**: 只衡量主实体抽取的好坏（不考虑关系和客实体）
- **Triple 指标**: 衡量完整三元组 (subject, relation, object) 的抽取准确度——主实体、客实体、关系**三者全部正确**才算对

### 9.2 `extract_sub(pred_sub_heads, pred_sub_tails)`
**文件**: [codes/utils/process.py:134-147](codes/utils/process.py#L134-L147)

功能: 从 head/tail 的一维预测张量中解码出实体跨度
输入: pred_sub_heads [seq_len], pred_sub_tails [seq_len]（值为 0/1）

算法:

  tails = 所有值为1的索引

算法:
  转置 → [num_rel, seq_len]
  对每种关系类型分别调用 extract_sub()
  为每个解码出的实体附上关系 ID
