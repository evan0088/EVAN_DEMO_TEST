## 1. 概述：知识图谱构建流程

知识图谱构建的核心步骤：

```
原始文本 → 实体识别(NER) → 关系抽取(RE) → 三元组(SPO) → 知识图谱
```

- **实体识别（NER）**：从非结构化文本中识别出命名实体（如疾病、症状、身体部位等）
- **关系抽取（RE）**：识别实体之间的语义关系，形成 `<主语, 谓语, 宾语>` 三元组（SPO Triplet）
- **知识融合**：将抽取的三元组进行实体对齐、消歧，构建完整的知识图谱

本项目以**医疗领域**为场景，实体类型包括：

| 实体类型 | 标签 | 说明 |
|----------|------|------|
| 治疗 | TREATMENT | 治疗方案、药物等 |
| 身体部位 | BODY | 人体部位名称 |
| 症状和体征 | SIGNS | 临床表现、症状 |
| 检查和检验 | CHECK | 医学检查项目 |
| 疾病和诊断 | DISEASE | 疾病名称、诊断结论 |

关系抽取任务涉及两类数据场景，关系类型分别如下：

**Pipeline模式关系类型**（共5种，娱乐领域）：

| ID | 关系类型 | 说明 |
|----|---------|------|
| 0 | 导演 | 影视作品的导演 |
| 1 | 歌手 | 歌曲的演唱者 |
| 2 | 作曲 | 歌曲的作曲者 |
| 3 | 作词 | 歌曲的作词者 |
| 4 | 主演 | 影视作品的主演 |

**Joint模式（CasRel）关系类型**（共18种，娱乐领域）：

| ID | 关系类型 | ID | 关系类型 | ID | 关系类型 |
|----|---------|----|---------|----|---------|
| 0 | 出品公司 | 6 | 歌手 | 12 | 出版社 |
| 1 | 国籍 | 7 | 所属专辑 | 13 | 主演 |
| 2 | 出生地 | 8 | 作词 | 14 | 导演 |
| 3 | 民族 | 9 | 作曲 | 15 | 编剧 |
| 4 | 出生日期 | 10 | 连载网站 | 16 | 上映时间 |
| 5 | 毕业院校 | 11 | 作者 | 17 | 成立日期 |

## 2. 命名实体识别（NER）

### 2.1 基于规则实现NER

**核心思想**：利用分词工具 + 关键词词表 + 正则匹配实现机构名抽取。

**技术流程**：

```
原始文本 → jieba词性标注分词 → 序列标注(S/O/E) → 正则匹配(S+O*E+) → 机构名提取
```

**关键步骤**：

1. **准备关键词词表**：预定义实体结尾词，如`['公司', '有限公司', '大学', '政府', '人民政府', '总局']`
2. **词性标注分词**：使用 `jieba.posseg.lcut()` 对文本进行分词并获得词性标注
3. **序列标注**（S-O-E标记法）：
   - `S`（Space）：地名关键词（词性为 `ns` 的词）
   - `E`（Entity）：机构结尾关键词（在关键词词表中的词）
   - `O`（Other）：其他词
4. **正则匹配**：使用 `re.compile('S+O*E+')` 匹配序列，提取至少一个地名(S) + 零或多个普通词(O) + 至少一个机构结尾词(E) 的模式
5. **实体拼接**：根据匹配的起止索引，将对应位置的单词拼接成完整的机构名

**代码位置**：[ner_rules_demo.py](code/1.基于规则实现NER/ner_rules_demo.py)

**适用场景**：
- 目标实体模式固定、规则明确
- 快速原型验证
- 数据标注不足时的冷启动

**局限性**：
- 依赖人工构建词表，覆盖面有限
- 无法处理未登录词和变体表达
- 规则维护成本高

### 2.2 基于深度学习实现NER

深度学习NER将问题建模为**序列标注（Sequence Labeling）**任务，使用BIO标注法（Begin-Inside-Outside）对每个字符进行标签预测。

#### BIO标注法

```
B-TREATMENT  → 治疗实体的开始
I-TREATMENT  → 治疗实体的内部/结尾
B-BODY       → 身体部位实体的开始
I-BODY       → 身体部位实体的内部/结尾
O            → 非实体
```

例如："右髋部疼痛" 标注为：`右/B-BODY 髋/I-BODY 部/I-BODY 疼/B-SIGNS 痛/I-SIGNS`

**项目中的标签体系**（共11个标签）：

| ID | 标签 | 含义 |
|----|------|------|
| 0 | O | 非实体 |
| 1 | B-TREATMENT | 治疗实体开始 |
| 2 | I-TREATMENT | 治疗实体内部 |
| 3 | B-BODY | 身体部位实体开始 |
| 4 | I-BODY | 身体部位实体内部 |
| 5 | B-SIGNS | 症状实体开始 |
| 6 | I-SIGNS | 症状实体内部 |
| 7 | B-CHECK | 检查实体开始 |
| 8 | I-CHECK | 检查实体内部 |
| 9 | B-DISEASE | 疾病实体开始 |
| 10 | I-DISEASE | 疾病实体内部 |

#### 2.2.1 BiLSTM 模型

**模型结构**：

```
Input(字符ID序列)
    ↓
Embedding层  [batch, seq_len, 300]     — 词向量嵌入
    ↓
BiLSTM层     [batch, seq_len, 256]     — 双向LSTM提取上下文
    ↓
Dropout层                              — 随机失活防过拟合
    ↓
Linear层     [batch, seq_len, 11]      — 映射到标签空间
    ↓
Output(每个字符的标签logits)
```

**关键设计**：

- **Embedding层**：每个字符映射为 `embedding_dim=300` 维的稠密向量
- **BiLSTM**：双向LSTM（`bidirectional=True`），隐层维度 `hidden_dim=256`（每个方向128维拼接）
- **掩码机制**：通过 `outputs * mask.unsqueeze(-1)` 将padding位置的输出置零，消除无效位置对训练的影响
- **损失函数**：CrossEntropyLoss（分类交叉熵）

**代码位置**：[ner_lstm.py](code/2.基于深度学习实现NER/LSTM_CRF/model/ner_lstm.py)

#### 2.2.2 BiLSTM + CRF 模型

**核心改进**：在BiLSTM输出层之后增加CRF（条件随机场）层，显式建模标签之间的转移约束。

**模型结构**：

```
Input(字符ID序列)
    ↓
Embedding层           [batch, seq_len, 300]
    ↓
BiLSTM层              [batch, seq_len, 256]
    ↓
Dropout层
    ↓
Linear层(发射分数)     [batch, seq_len, 11]    — 每个位置属于各标签的得分（发射分数）
    ↓
CRF层(转移分数+维特比解码)                     — 学习标签间转移概率，输出最优路径
    ↓
Output(最优标签序列)
```

**CRF层核心组件**：

1. **发射分数（Emission Score）**：由BiLSTM+Linear层输出，表示每个位置属于各标签的得分
2. **转移分数（Transition Score）**：CRF的可训练参数矩阵 `[tag_size, tag_size]`，学习标签之间的转移概率（如 `B-TREATMENT → I-TREATMENT` 概率高，`B-TREATMENT → B-DISEASE` 概率低）
3. **维特比解码（Viterbi Decode）**：基于发射分数和转移分数，求解全局最优标签路径

**训练与推理的区别**：

| 阶段 | 方法 | 说明 |
|------|------|------|
| 训练 | `log_likelihood()` | CRF前向算法计算对数似然，损失 = `-log(P(真实路径))` |
| 推理 | `viterbi_decode()` | 维特比算法求解分数最高的标签路径 |

**关键要点**：
- CRF的mask需要是 `BoolTensor` 类型
- CRF可训练参数就是转移分数矩阵，大小为 `[tag_size, tag_size]`
- 该模型能隐式学习到 BIO 约束（如 I-XXX 不应出现在 B-XXX 之前）

**代码位置**：[ner_lstm_crf.py](code/2.基于深度学习实现NER/LSTM_CRF/model/ner_lstm_crf.py)

#### 2.2.3 BiLSTM + Multi-Head Self-Attention 模型

**核心改进**：用Multi-Head Self-Attention替代CRF层，通过自注意力机制捕捉全局标签依赖。

**模型结构**：

```
Input(字符ID序列)
    ↓
Embedding层                [batch, seq_len, 300]
    ↓
BiLSTM层                   [batch, seq_len, 256]
    ↓
Multi-Head Self-Attention  [batch, seq_len, 256]   — 每个位置关注全句所有位置
    ↓
残差连接 + LayerNorm       [batch, seq_len, 256]   — 保留LSTM信息 + 归一化
    ↓
Dropout + 掩码置零
    ↓
Linear层                   [batch, seq_len, 11]
    ↓
Output(标签logits) + CrossEntropyLoss
```

**关键设计**：

| 组件 | 作用 |
|------|------|
| `nn.MultiheadAttention` | 8头自注意力，每个头关注不同方面（语法、语义、标签相容性），隐式学习BIO约束 |
| 残差连接 `lstm_out + attn_out` | 保留BiLSTM的原始特征，注意力学习"增量"信息 |
| `nn.LayerNorm` | 归一化稳定训练，加速收敛 |
| `key_padding_mask` | 让padding位置不参与注意力计算 |

**与BiLSTM+CRF的对比**：

| 维度 | BiLSTM + CRF | BiLSTM + Attention |
|------|-------------|-------------------|
| 序列依赖建模 | CRF转移矩阵 | Self-Attention全局注意力 |
| 解码方式 | 维特比解码（动态规划） | argmax直接解码 |
| 损失函数 | 负对数似然（CRF前向算法） | 交叉熵损失 |
| 训练稳定性 | 可能出现梯度爆炸 | 残差连接+LayerNorm更稳定 |
| 推理速度 | 较慢（维特比算法） | 较快（argmax） |

**代码位置**：[ner_lstm_attention.py](code/2.基于深度学习实现NER/LSTM_CRF/model/ner_lstm_attention.py)

---

### 2.3 模型对比

| 维度 | 规则方法 | BiLSTM | BiLSTM+CRF | BiLSTM+Attention |
|------|---------|--------|------------|-----------------|
| 实现复杂度 | 低 | 中 | 高 | 中高 |
| 泛化能力 | 差 | 中 | 中高 | 中高 |
| 标签约束 | 无（正则代替） | 无 | 显式（转移矩阵） | 隐式（注意力） |
| 训练难度 | 无 | 低 | 中 | 低 |
| 推理速度 | 快 | 快 | 中 | 快 |
| 适用场景 | 模式固定 | 基线模型 | 高精度需求 | 高效训练推理 |

## 3. 关系抽取（RE）

关系抽取在NER的基础上，识别已抽取实体之间的语义关系，输出 `<主语(Subject), 谓语(Predicate), 宾语(Object)>` 三元组。

#### 关系抽取任务的三种经典问题

根据文本中三元组的重叠情况，关系抽取面临以下三类问题：

| 问题类型 | 英文 | 特征 | 示例 |
|---------|------|------|------|
| **正常关系 (Normal)** | Normal | 三元组之间无重叠，仅有一个实体对及一种关系 | "《人间》是王菲演唱歌曲" → (王菲, 歌手, 人间) |
| **单一实体重叠 (SEO)** | Single Entity Overlap | 一个实体参与到了多个关系中（共享同一个主语或宾语） | "叶春叙出生于浙江，毕业于黄埔军校" → (叶春叙, 出生地, 浙江)、(叶春叙, 毕业院校, 黄埔军校) |
| **实体对重叠 (EPO)** | Entity Pair Overlap | 同一个实体对之间存在多种不同的关系 | "周星驰导演了《功夫》，并担任男主角" → (周星驰, 导演, 《功夫》)、(周星驰, 演员, 《功夫》) |

```
Normal:            SEO:                   EPO:
  S──→O             S──→O1                S──→O (关系1)
                     └──→O2               └──→O (关系2)
```

> **关键结论**：Pipeline模式难以处理SEO和EPO重叠问题；CasRel的Joint模式通过"先识别主实体，再针对每个主实体预测其所有客实体及关系"的级联策略，能够同时解决SEO和EPO问题。

### 3.1 基于Pipeline实现关系抽取

**Pipeline模式**：将实体识别和关系分类分为两个独立的阶段。

```
原始文本 → 实体识别(NER) → 实体对 → 关系分类模型 → 三元组
```

#### 模型架构：BiLSTM + Attention 关系分类

**输入**：句子文本 + 两个实体的相对位置编码

**模型结构**：

```
Input(句子字符ID)      Input(实体1位置编码)      Input(实体2位置编码)
    ↓                      ↓                        ↓
Word Embedding        Pos1 Embedding            Pos2 Embedding
    ↓                      ↓                        ↓
    └──────────────────────┴────────────────────────┘
                     拼接 [word_emb + pos1_emb + pos2_emb]
                           ↓
                      Dropout
                           ↓
                      BiLSTM层 [batch, seq_len, 200]
                           ↓
                      Dropout
                           ↓
                      Attention 注意力机制
                           ↓
                      tanh激活 + Dropout + squeeze
                           ↓
                      Linear层 → 关系类别概率
                           ↓
                      Output(关系分类结果)
```

**关键设计**：

1. **位置编码（Position Embedding）**：
   - 计算每个词相对于两个实体的位置偏移 `pos = word_index - entity_index`
   - 位置值映射到 `[0, 142]` 范围（负数用70偏移量处理）
   - 超出范围的统一映射到边界值

2. **注意力机制**：
   - 使用可训练的注意力权重向量 `att_weight [1, 1, hidden_dim]`
   - 对LSTM输出做 `tanh` → 与权重矩阵乘 → `softmax` → 加权求和
   - 让模型关注句子中对关系判断最重要的部分

3. **输入维度**：`embedding_dim(128) + pos_dim(32) × 2 = 192` → LSTM → `hidden_dim(200)`

**代码位置**：[model.py](code/3.基于pipeline实现关系抽取/Bilstm_Attention_RE/model.py) | [train.py](code/3.基于pipeline实现关系抽取/Bilstm_Attention_RE/train.py) | [predict.py](code/3.基于pipeline实现关系抽取/Bilstm_Attention_RE/predict.py)

**Pipeline模式特点**：
- ✅ 各阶段独立，灵活可替换
- ✅ 模型相对简单，训练成本低
- ❌ 误差传播：NER的错误会直接影响RE
- ❌ 忽略两个任务之间的信息交互

### 3.2 基于Joint方法实现关系抽取（CasRel）

**Joint模式**：实体识别与关系抽取联合建模，共享编码层，同时完成两个任务。

#### CasRel模型架构

CasRel = **Cas**cade + **Rel**ation，采用级联式的联合抽取策略。

**整体流程**：

```
Step 1: 识别主实体(Subject)
    输入文本 → BERT编码 → 线性层+sigmoid → 主实体头部位置 + 主实体尾部位置
                              ↓
Step 2: 对每个主实体，识别对应的客实体和关系
    主实体特征 + BERT编码 → 线性层+sigmoid → 客实体头部位置+关系 + 客实体尾部位置+关系
                              ↓
Step 3: 组装三元组
    主实体 + 关系 + 客实体 → SPO三元组
```

**模型结构详解**：

```
Input [batch, seq_len]
    ↓
BERT编码层 (bert-base-chinese)  [batch, seq_len, 768]
    ↓
    ├──→ sub_heads_linear  [768→1] + sigmoid  → 主实体头部概率 [batch, seq_len, 1]
    ├──→ sub_tails_linear  [768→1] + sigmoid  → 主实体尾部概率 [batch, seq_len, 1]
    │
    └──→ 对每个预测的主实体：
         ├─ 构建 sub_head2tail 掩码 [batch, 1, seq_len]
         ├─ 主实体向量 = matmul(sub_mask, encoded_text) / sub_len
         ├─ 融合特征 = encoded_text + 主实体向量
         │
         ├─→ obj_heads_linear [768→18] + sigmoid → 客实体头部+关系 [batch, seq_len, num_rel]
         └─→ obj_tails_linear [768→18] + sigmoid → 客实体尾部+关系 [batch, seq_len, num_rel]
```

**四个核心线性层**：

| 线性层 | 输入维度 | 输出维度 | 作用 |
|--------|---------|---------|------|
| `sub_heads_linear` | 768 | 1 | 判断每个位置是否是主实体的起始位置 |
| `sub_tails_linear` | 768 | 1 | 判断每个位置是否是主实体的结束位置 |
| `obj_heads_linear` | 768 | 18 | 判断每个位置是否是某类客实体的起始位置（18种关系） |
| `obj_tails_linear` | 768 | 18 | 判断每个位置是否是某类客实体的结束位置（18种关系） |

**客实体预测的多通道设计**：

`obj_heads_linear` 和 `obj_tails_linear` 的输出维度为 `num_rel=18`，每个通道对应一种关系类型。模型通过一次前向传播，同时完成**客实体定位 + 关系分类**两个任务：

```
obj_heads [batch, seq_len, 18]
    ↓ 逐通道解读
通道0 (出品公司):  [0, 0, 0, 1, 0, ...]  →  位置3是"出品公司"关系的客实体头部
通道1 (国籍):      [0, 1, 0, 0, 0, ...]  →  位置1是"国籍"关系的客实体头部
通道6 (歌手):      [1, 0, 0, 0, 0, ...]  →  位置0是"歌手"关系的客实体头部
...
```

> **核心机制**：通道索引 = 关系ID，通道内的位置 = 客实体在句中的位置。因此 CasRel 输出的是 `(关系类型, 客实体起始位置, 客实体结束位置)` 三元信息，实现了关系与实体位置的联合预测。

**主实体与编码文本融合机制**：

```
主实体向量 = sub_head2tail_mask ⊙ encoded_text / sub_len  （平均池化）
融合特征 = encoded_text + 主实体向量（广播到每个位置）
```

这个设计的巧妙之处：将主实体的语义信息注入到每个位置的表示中，使得模型在预测客实体时"知道"当前主实体是什么。

**损失函数**：四个BCELoss之和

```
总损失 = BCE(主实体头部) + BCE(主实体尾部) + BCE(客实体头部) + BCE(客实体尾部)
```

**后处理关键函数**：

- `extract_sub()`：从头部/尾部概率中提取实体 `(head_idx, tail_idx)`（要求 `tail >= head`）
- `extract_obj_and_rel()`：提取客实体及其关系类型 `(rel_id, start, end)`
- `convert_score_to_zero_one()`：以0.5为阈值二值化概率

**代码位置**：[casrel_model.py](code/4基于joint实现关系抽取/Casrel_RE/codes/model/casrel_model.py) | [train.py](code/4基于joint实现关系抽取/Casrel_RE/codes/train.py) | [predict.py](code/4基于joint实现关系抽取/Casrel_RE/codes/predict.py)

---

### 3.3 Pipeline vs Joint 对比

| 维度 | Pipeline (BiLSTM+Attn) | Joint (CasRel+BERT) |
|------|------------------------|---------------------|
| 编码器 | Word Embedding + BiLSTM | BERT预训练模型 |
| 实体识别 | 独立NER阶段 | 联合在模型中（sub_heads/tails） |
| 关系分类 | 独立分类器 | 联合在模型中（obj_heads/tails） |
| 位置信息 | 手工设计位置编码 | 通过BERT注意力隐式建模 |
| 误差传播 | 存在（NER错误→RE错误） | 缓解（共享编码，联合优化） |
| 参数量 | 小（~百万级） | 大（BERT 110M + 线性层） |
| 训练成本 | 低 | 高 |
| 适用场景 | 数据量少、计算资源有限 | 数据量充足、追求高精度 |

## 4. 数据处理与标注

### 4.1 数据标注与BIO标注法

**原始数据格式**（医疗场景）：

```
右髋部	21	23	身体部位
疼痛	27	28	症状和体征
肿胀	29	30	症状和体征
```

每行表示：`实体文本 \t 起始索引 \t 结束索引 \t 实体类型`

**BIO转换过程**：

1. 基于标注信息获取每个字符所属的实体类型
2. 实体起始字符标记为 `B-{类型}`
3. 实体内部/结尾字符标记为 `I-{类型}`
4. 非实体字符标记为 `O`

**转换结果示例**：

```
右	B-BODY
髋	I-BODY
部	I-BODY
疼	B-SIGNS
痛	I-SIGNS
```

转换逻辑参见 [process.py](code/2.基于深度学习实现NER/LSTM_CRF/utils/process.py) 中的 `TransferData` 类。

### 4.2 数据预处理与编码

#### NER任务的数据编码

| 步骤 | 说明 |
|------|------|
| 句子分割 | 按标点符号 `。?!！？` 分割句子，构造 (x, y) 样本对 |
| 词表构建 | 遍历所有字符构建 `word2id` 映射，预留 `PAD(id=0)` 和 `UNK` |
| Tokenize | 将句子中的每个字符转为对应的 `word2id` |
| 长度补齐 | 使用 `pad_sequence()` 对batch内句子补齐到相同长度 |
| 注意力掩码 | `attention_mask = (input_ids != 0).long()` 标记有效/填充位置 |

#### 关系抽取任务的数据编码

**Pipeline模式**：
- 句子转为字符ID序列并补齐到 `max_len`
- 位置信息 `pos = word_index - entity_index` 映射到 `[0, 142]`
- 边界值：`< -70 → 0`, `-70~70 → +70`, `> 70 → 142`
- 补齐值使用 `142`（代表超出范围）

**Joint模式（CasRel）**：
- 使用 `BertTokenizer` 将句子编码为 `input_ids + attention_mask`
- `create_label()` 函数构造四个监督信号张量：
  - `sub_heads`：主实体头部位置 [seq_len]
  - `sub_tails`：主实体尾部位置 [seq_len]
  - `obj_heads`：客实体头部+关系 [seq_len, num_rel]
  - `obj_tails`：客实体尾部+关系 [seq_len, num_rel]

### 4.3 数据集构建与加载

所有任务均基于 PyTorch 的 `Dataset` + `DataLoader` 架构：

```
自定义Dataset类(继承torch.utils.data.Dataset)
    ├── __init__()  : 加载数据
    ├── __len__()   : 返回数据量
    └── __getitem__(): 返回单个样本

自定义 collate_fn 函数
    ├── 对batch样本进行编码
    ├── 长度补齐(pad_sequence)
    └── 构造attention_mask

DataLoader(dataset, batch_size, collate_fn)
    └── 输出可迭代的数据批次
```

**数据划分**：
- 训练集/验证集按比例切分（NER中 ~6200/1600）
- Joint模型中分为 train/dev/test 三个独立文件

## 5. 模型训练与评估

### 5.1 训练流程

**统一训练范式**：

```
配置加载 → 数据迭代器构建 → 模型实例化 → 优化器定义 → 训练循环
```

**训练循环核心步骤**：

```python
for epoch in range(epochs):
    for batch in train_dataloader:
        1. 前向传播: outputs = model(inputs)
        2. 计算损失: loss = criterion(outputs, labels)
        3. 梯度清零: optimizer.zero_grad()
        4. 反向传播: loss.backward()
        5. 参数更新: optimizer.step()
        6. 日志记录: 损失、准确率等
```

**关键超参数配置**：

| 参数 | NER(LSTM_CRF) | RE(Pipeline) | RE(CasRel) |
|------|---------------|-------------|------------|
| embedding_dim | 300 | 128 | 768（BERT）|
| hidden_dim | 256 | 200 | 768（BERT）|
| batch_size | 8 | 32 | 8 |
| epochs | 5 | 50 | 10 |
| learning_rate | 2e-3 | 1e-3 | 1e-5 |
| dropout | 0.2 | 0.2 | — |
| 优化器 | — | Adam | AdamW |
| 设备 | CUDA/CPU | CPU/MPS | MPS |

**学习率选择原则**：
- LSTM模型：`1e-3 ~ 2e-3`
- BERT（仅微调输出层）：`1e-5`
- BERT（全量微调）：`1e-8`

### 5.2 评估指标

**NER任务**：序列级别的标签准确率

**RE任务（CasRel）**：实体级别和三元组级别的精确率(P)、召回率(R)、F1值

```
P = TP / (TP + FP)    — 精确率：预测为正的样本中真正的比例
R = TP / (TP + FN)    — 召回率：真正例中被预测出来的比例
F1 = 2 * P * R / (P + R)  — F1：精确率和召回率的调和平均
```

评估维度包括：
- **主实体（Sub）**：主实体抽取的 P/R/F1
- **三元组（Triple）**：完整SPO三元组的 P/R/F1

### 5.3 模型保存与预测

**模型保存**：
```python
# 定期保存
torch.save(model.state_dict(), 'save_model/epoch_X_model_Y.pth')
# 最优模型
torch.save(model.state_dict(), 'save_model/best_f1.pth')
```

**模型加载与预测**：
```python
# 加载模型参数
model.load_state_dict(torch.load('save_model/model.pth', map_location=device))
# 切换评估模式
model.eval()
# 禁用梯度计算
with torch.no_grad():
    output = model(inputs)
    prediction = torch.argmax(output, dim=1)  # 分类任务
```

## 附录：技术演进路线

```
阶段1: 规则方法
  基于规则实现NER（jieba + 关键词 + 正则）
    ├── 优点：快速、可解释、无需标注数据
    └── 局限：规则覆盖有限、泛化能力差
          ↓
阶段2: 深度学习基线
  BiLSTM 序列标注模型
    ├── 优点：自动特征提取、泛化能力强
    └── 局限：标签间无约束、可能输出非法序列
          ↓
阶段3: CRF增强
  BiLSTM + CRF（维特比解码 + 转移矩阵）
    ├── 优点：显式建模标签转移约束、全局最优
    └── 局限：训练慢、梯度不稳定
          ↓
阶段4: Attention替代
  BiLSTM + Multi-Head Self-Attention
    ├── 优点：隐式学习标签依赖、训练稳定、推理快速
    └── 局限：依赖足够训练数据
          ↓
阶段5: 关系抽取 — Pipeline
  NER → BiLSTM+Attention分类器 → 三元组
    ├── 优点：模块化、灵活替换
    └── 局限：误差传播
          ↓
阶段6: 关系抽取 — Joint + 预训练
  CasRel + BERT 联合抽取
    ├── 优点：端到端、缓解误差传播、精度高
    └── 局限：计算资源需求大
```
